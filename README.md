# 让 AI 接管你的微信小号

> 在一台虚拟机里跑 Linux 版微信，用「截图 → OCR → 大模型 → 模拟输入」的方式，
> 让 AI 接管一个微信小号。单聊、群聊（@ 才回）、图片、表情、动图、语音都能处理，掉线能自己恢复。

**没有官方 API**：微信不提供个人号接口，这套方案靠"看屏幕 + 打字"，和真人操作没有区别。
所以它能做的事有边界，搭之前请先看下面的「能 / 不能」。

---

## 它能做什么

| 场景 | 行为 |
|---|---|
| 单聊 | 收到消息就回（文字、图片、表情包、动图、语音都能处理） |
| 群聊 · 被 @ | 回，并且能接上刚才的对话；引用消息也能看见 |
| 群聊 · 没 @ | **工作时间不说话**；空闲时段可能自己插一句（可关） |
| 掉线 | 自动点登录 → 手机上点一下确认 → 恢复，不用扫码 |
| 进程崩了 | 看门狗自动拉起，异常发邮件 |

## 它不能做什么

- ❌ 群发、加好友、刷消息 —— 只能回复现有会话
- ❌ 读懂艺术字、低对比度文字、严重口音的语音
- ❌ 保证长期免维护：微信界面一升级，坐标和阈值可能要重新标定

---

## 为什么值得看这份文档

**难点从来不是调模型，而是屏幕上的位置和顺序都不可靠。**

这份文档里有 **15 个实测踩过的坑**，每一条都会让你多花几小时：

- `xdotool key Return` 在微信 4.x 里**根本不生效**，文字留在输入框而脚本以为发出去了
- 整屏 OCR 会**漏掉最下面那条**消息
- 用 x 坐标判断"谁发的"，会把长消息判错
- 语音气泡右边那个 `Convert to text` 会被 OCR 读成一条消息，把语音顶成"不是最新"
- ……

完整清单在 [docs/manual.md](docs/manual.md) 第七节。

## 怎么用

### 如果你想自己搭

读 [docs/manual.md](docs/manual.md)，按第五节的 8 个阶段推进，每阶段末尾有验收命令。

**你需要准备**：Windows + VirtualBox、Ubuntu、Linux 版微信、一个能开**应用分身**的安卓手机、
一个能命令行调用的大模型。

> 手机应用分身是分水岭：没有它，小号掉线后必须在电脑前扫码；
> 有了它，掉线只需要手机上点一下。

### 如果你想让 AI 帮你搭

把这两样丢给 AI（Claude / GPT / DeepSeek 都行）：

1. 本仓库链接
2. [prompt.md](prompt.md) 里的那段指令

AI 会通读手册、按阶段实施、逐项验收。**记得提醒它"坐标不要抄，要按你的环境重新标定"**。
